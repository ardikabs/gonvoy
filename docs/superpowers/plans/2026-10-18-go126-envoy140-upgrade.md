# Go 1.26.5 + Envoy v1.40.0 Upgrade Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move gonvoy atomically to Go 1.26.5 and Envoy v1.40.0 with today's unit + e2e expectations passing unchanged, or stop with documented evidence where v1.40 makes that impossible.

**Architecture:** Recon-first, then pins, then code. A read-only API-diff recon of Envoy's Go SDK (v1.31.2 → v1.40.0) for exactly the symbols gonvoy uses gates everything; toolchain and dependency pins follow; code changes are compile-minimal per the recon; e2e on v1.40 is the relevance gate with a stop-and-escalate rule.

**Tech Stack:** Go 1.26.5, `github.com/envoyproxy/envoy` v1.40.0 Go SDK, Envoy `contrib-v1.40-*` image, Docker e2e harness, golangci-lint (bumped to a Go-1.26-capable version).

**Spec:** `docs/superpowers/specs/2026-10-18-go126-envoy140-upgrade-design.md`

## Global Constraints

- Go directive literal `go 1.26.5` in all 9 `go.mod` files + `go.work` (repo precedent uses patch form).
- Envoy SDK exactly `v1.40.0`; all other deps minor/patch within current majors only — no major jumps.
- Envoy image references target the v1.40 line only; accepted compat gap from v1.31, no shims for older Envoy.
- No expectation edits to hide v1.40 behavior change: failing-today expectations become BREAKING evidence + stop, not edited tests.
- All Go edits follow `gonvoy-code-style` + `gonvoy-naming-convention` skills (2-group imports, `Http` not `HTTP`, `var()` sentinels + `%w`, single-letter receivers, godoc).
- `GODEBUG=cgocheck=0` stays for filter builds.

## Review Focus

- `filter.so` built under Go 1.26.5 Green Tea GC + cgo still loads in Envoy v1.40 (expect: loads, no crash on first request) → pinned by Task 6 Step 1.
- Trailer-phase methods (`DecodeTrailers`/`EncodeTrailers` with `RequestTrailerMap`/`ResponseTrailerMap`) still satisfy `api.StreamFilter` on v1.40 (expect: compiles, `api.Continue` passthrough works) → pinned by Task 5 Step 3 + Task 6 Step 1.
- `X-Content-Operation` body-access + `StopNoBuffer`/`StopAndBuffer` streaming semantics unchanged on v1.40 (expect: `http_body` e2e expectations pass unedited) → pinned by Task 6 Step 1.
- `xds.TypedStruct` config parse + `gjson`/protobuf minor-bump wire compat (expect: `configparser` tests pass unedited) → pinned by Task 5 Step 3.
- Metrics (`CounterMetric`/`GaugeMetric`) + `LogType` (`Debug`/`Info`/`Error`) + `LocalReply` statuses still exist with same names (expect: no renames; mocks regenerate cleanly) → pinned by Task 5 Steps 2–3.
